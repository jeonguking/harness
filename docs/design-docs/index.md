# design-docs — 설계 문서

설계 문서는 **검증 상태**와 **핵심 신념**을 명시합니다. 살아있는 문서를 유지하고,
결정이 바뀌면 검증 상태를 갱신하세요.

## 색인

- `core-beliefs.md` — 리포지터리의 핵심 신념 (골든 룰 요약본)

## 템플릿 (새 설계 문서 작성 시)

```markdown
# <제목>

- 상태: DRAFT | PROPOSED | ACCEPTED | SUPERSEDED
- 결정일: YYYY-MM-DD
- 관련: (링크)

## 배경

## 결정

## 검증 상태

- [ ] 아키텍처 검토 완료
- [ ] 구조 테스트/린터 반영
- [ ] 실행 계획 연결

## 대안 (선택)
```

## 유지 규칙

- 상태가 DRAFT인 문서는 완성되기 전에 문서를 참조하는 작업을 하지 마세요.
- SUPERSEDED 문서는 삭제하지 말고 상태를 바꿔 기록을 남기세요.
