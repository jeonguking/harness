# 핵심 신념 (Core Beliefs)

이 문서는 리포지터리에서 **변하지 않는** 신념입니다. `docs/DESIGN.md`(골든 룰)와
`ARCHITECTURE.md`(계층 맵)의 원칙 요약입니다.

## 1. 에이전트가 직접 추론할 수 있어야 한다

에이전트가 컨텍스트에서 접근할 수 없는 지식(문서, 채팅, 머릿속)은 존재하지 않는 것과 같다.
모든 지식은 이 리포지터리 안, 버전 관리되는 아티팩트(코드/마크다운/스키마/실행 계획)로만
표현한다. "3개월 후 신규 진입자가 알 수 없는 것"과 같은 기준으로 문서를 평가한다.

## 2. 맵이지 백과사전이 아니다

`AGENTS.md`는 목차입니다. 깊이는 `docs/`에 있습니다. 한 파일에 모든 것을 담으려 하면
컨텍스트가 희소해지고, 지침이 많아지면 지침이 되지 못합니다.

## 3. 불변 조건은 기계적으로 강제한다

문서화만으로는 드리프트를 막지 못합니다. 경계, 의존성 방향, 명명, 파일 크기 같은
불변 조건은 맞춤 린터/구조 테스트로 강제하고, 오류 메시지에 수정 지침을 담는다.

## 4. 경계에서 파싱한다

데이터는 추측한 형태로 사용하지 않는다. 경계에서 검증된 형태로 파싱하거나,
유형 지정된 SDK에 위임한다. (parse, don't validate)

## 5. 인적 QA는 병목이다

인간의 시간과 주의력은 고정 제약이다. UI/로그/메트릭을 에이전트가 직접 읽고
이해할 수 있게 만드는 것이 속도다.

## 6. 자율성은 경계 안에서

경계, 정확성, 재현성이 중요한 곳은 중앙에서 규칙을 정한다. 그 외에는 로컬 자율성.
"중앙에서 경계를, 로컬에서 자유를."

## 7. 기술 부채는 매일 조금씩

"AI 슬로프"를 주 1회 대청소하는 것은 확장되지 않는다. 정기적 정리 프로세스
(doc-gardening, quality 업데이트, 대상 리팩터링 PR)로 매일 조금씩 해결한다.
