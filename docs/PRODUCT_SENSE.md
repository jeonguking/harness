# PRODUCT_SENSE.md — 제품 원칙

사람이 에이전트에게 "취향"을 알려주는 것처럼, 에이전트가 제품 결정을 내릴 때 따르는 원칙.
신규 팀원을 온보딩하듯 에이전트에게도 이 정보를 제공합니다.

## 원칙

1. **실사용자 우선** — 기능은 내부 파워 유저를 포함한 실제 사용자에게 의미 있어야 한다.
   출력을 위한 출력 금지.
2. **수용 기준으로 피드백을** — 사용자 피드백/버그는 산문이 아니라 수용 기준으로 전환한다.
3. **처리량 대비 병목** — 인간 QA가 병목이므로 에이전트가 스스로 검증 가능한 형태
   (로깅, 메트릭, UI 여정)로 제품을 설계한다.
4. **단순함은 미덕** — "지루한" 기술과 예측 가능한 구조를 선호. 합성이 어려운 마법 금지.

## 작성 규칙

- 기능별 제품 스펙은 `docs/product-specs/`에 작성 (템플릿은 `docs/product-specs/index.md` 참고).
- 결정 배경은 항상 "왜"를 포함한다. "무엇"만 있으면 다음 에이전트가 재발견해야 한다.
