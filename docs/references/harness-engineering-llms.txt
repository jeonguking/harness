# 출처: https://openai.com/ko-KR/index/harness-engineering/

하네스 엔지니어링: 에이전트 우선 세계에서 Codex 활용하기 (OpenAI, 2026-02-11, Ryan Lopopolo)

본 리포지터리 스캐폴드가 따르는 원칙의 요약. 원문 참조용 스냅샷.

## 핵심 교훈

1. 빈 git 리포지터리에서 시작 — 초기 스캐폴드(구조, CI, 포맷 규칙, 패키지 관리자,
   앱 프레임워크)를 소수 템플릿으로 생성. AGENTS.md도 에이전트가 작성.
2. 엔지니어의 역할 = 환경 설계 + 의도 명시 + 피드백 루프. 코드 작성이 아님.
3. 애플리케이션을 에이전트가 읽을 수 있게: worktree별 인스턴스, Chrome DevTools MCP,
   DOM 스냅샷/스크린샷/탐색 스킬, 로컬 관측 가능성 스택(LogQL/PromQL/TraceQL).
4. 지식베이스를 기록 시스템으로: AGENTS.md는 목차(~100줄). 하나의 거대 매뉴얼은
   컨텍스트 희소, "모두 중요 = 아무것도 중요하지 않음", 드리프트, 검증 곤란으로 실패.
5. 에이전트 가독성이 목표: 컨텍스트 밖 지식은 존재하지 않는 것. 내부화 가능한
   추상화 선호. 불투명한 업스트림 동작은 자체 재구현도 고려.
6. 아키텍처·취향 강제: 문서화만으론 불가. 맞춤 린터/구조 테스트로 불변 조건 강제.
   각 비즈니스 도메인 = Types → Config → Repo → Service → Runtime → UI,
   교차 관심사(인증·커넥터·텔레메트리·기능 플래그) = Providers로만 유입.
7. 병합 철학: 최소 차단 게이트, 짧은 PR, 불안정 테스트는 후속 실행으로.
8. 에이전트가 생성: 제품 코드, 테스트, CI, 문서, 평가 하네스, 리뷰 응답, 저장소 관리 스크립트.
9. 자율성 증가: 검증→재현→구현→검증→PR→피드백→병합까지 한 프롬프트로.
10. 엔트로피/GC: 골든 룰 인코딩 + 정기 정리 프로세스. 공유 유틸리티 선호,
    "YOLO 탐색" 금지. 품질 등급 갱신 + 대상 리팩터링 PR을 자동 병합.

## 본 스캐폴드 반영 지점

- `AGENTS.md`: 목차/맵 (~100줄)
- `ARCHITECTURE.md`: 계층 도메인 아키텍처 + Providers
- `docs/`: 지식베이스 (design-docs, exec-plans, generated, product-specs, references)
- `docs/DESIGN.md`: 골든 룰
- `scripts/`: 기계적 검증 (맵·크로스링크·신선도·아키텍처)
- `.github/workflows/`: CI 검증 작업
