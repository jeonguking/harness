# RELIABILITY.md — 안정성 기준

에이전트가 변경 후 안정성을 판단할 때 따르는 기준.

## 기준

1. **예측 가능한 구조** — 엄격한 경계와 제한된 허용 에지. 마법적 동작 금지.
2. **시작 시간** — "서비스 시작이 Nms 이내에 완료" 같은 명시적 SLO를 프롬프트로 검증 가능해야 함.
3. **성능** — 핵심 사용자 여정에서 어떤 스팬도 임계치(예: 2초)를 초과하지 않도록.
4. **재현 가능성** — 버그는 에이전트가 재현·수정·검증할 수 있어야 한다.
   (worktree별 인스턴스, 관측 가능성 스택, UI 여정 스냅샷)
5. **테스트 불안정성** — 병합을 무기한 막지 않는다. 후속 실행으로 해결하거나
   `docs/exec-plans/tech-debt-tracker.md`에 기록.

## 관측 가능성

- 로그/메트릭/추적은 에이전트가 조회 가능해야 한다 (LogQL/PromQL/TraceQL 식).
- 관측 스택은 작업별로 격리되고 작업 완료 후 정리된다.

## 병합 철학

- 병합 게이트는 최소. PR은 수명이 짧다.
- 에이전트 처리량이 인간 주의력을 초과하는 환경에서는 수정 비용이 저렴하고 대기 비용이 크다.
- 재검토는 후속 실행으로.
