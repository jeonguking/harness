## 4. 요구사항

### 4.1 기능 요구사항 (FR)

요구사항은 **검증 가능한 수용 기준**과 함께 작성합니다. 각 항목에 고유 ID를 붙입니다.

| ID  | 요구사항                          | 우선순위 | 수용 기준 (검증 가능)                |
| --- | --------------------------------- | -------- | ------------------------------------ |
| FR-1 | 사용자는 이메일로 가입할 수 있다 | P0       | 가입 후 로그인이 가능한지 테스트      |
| FR-2 | ...                               |          | ...                                  |

### 4.2 비기능 요구사항 (NFR)

- 성능: "서비스 시작이 800ms 이내에 완료" 등 명시적 기준
- 안정성: 핵심 사용자 여정 스팬이 2초 초과 금지 등
- 보안: OWASP Top 10 준수 (`docs/SECURITY.md`)
- 가용성 / 확장성 / 규정 준수

### 4.3 데이터 요구사항

- 저장·조회할 데이터 정의 (스키마는 `docs/generated/db-schema.md`)
- 경계 파싱 규칙: 입력 형태는 추측하지 말고 스키마로 검증

### 4.4 UI/UX 요구사항

- 화면·여정 정의 (에이전트가 DOM 스냅샷으로 검증 가능해야 함)
