# SECURITY.md — 보안 기준

에이전트가 생성한 코드에 적용되는 보안 원칙.

## 원칙

1. **비밀은 저장소에 넣지 않는다** — 시크릿, 키, 토큰을 커밋 금지. `.gitignore`로 보호.
2. **경계 검증** — 사용자 입력, 네트워크 데이터는 경계에서 파싱/검증. (parse, don't validate)
3. **최소 권한** — Providers로 유입되는 인증/권한은 최소 권한 원칙.
4. **공급망** — 의존성은 고정/검증된 것만. 불투명한 업스트림 동작 대신 검증 가능한 구현 선호.
5. **관측** — 보안 관련 사건은 로그에 남기고, 로그는 에이전트가 조회 가능해야 한다.

## OWASP Top 10

변경 검토 시 `security` 에이전트가 OWASP Top 10(2021)을 기준으로 취약점을 점검합니다.

| 항목 | 초점                                            |
| ---- | ----------------------------------------------- |
| A01  | 접근 통제 (IDOR, 권한 상승)                     |
| A02  | 암호화 실패 (평문, 취약 알고리즘, 시크릿 노출)  |
| A03  | 주입 (SQL, 명령어, 템플릿)                      |
| A04  | 안전하지 않은 설계 (신뢰 경계, 위협 모델링)     |
| A05  | 보안 설정 오류 (과도한 권한, 기본 자격증명)     |
| A06  | 취약하고 오래된 구성 요소 (의존성)              |
| A07  | 식별 및 인증 실패                               |
| A08  | 소프트웨어/데이터 무결성 실패                   |
| A09  | 로깅/모니터링 실패                              |
| A10  | SSRF                                            |

세부 절차는 `.opencode/agent/security.md` 참조.

## 점검

- 커밋 전에 시크릿 스캔 (git diff 검토, `scripts/check.sh`에서 수행).
- 변경마다 `security` 에이전트(OWASP Top 10) 리뷰 병행.
- 보안 취약점은 `docs/exec-plans/tech-debt-tracker.md`에 기록.
